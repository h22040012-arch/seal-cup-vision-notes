# 工程设计笔记

## 先固定模型契约

适配器需要明确：输入是全图还是 ROI、像素格式、通道顺序、缩放插值、letterbox 填充值、张量布局和归一化；输出需要明确坐标系、类别映射、分数语义及是否已执行 NMS。不能只因为输出看起来像六列，就猜测它是坐标、分数和类别。

使用自己有权公开或自行生成的图片建立预处理基准；保存原始字节摘要、裁剪尺寸和张量摘要。摘要也不应来自保密图片，以免成为关联内部数据的指纹。不同运行环境允许的数值误差应通过独立数据评估，尤其关注门槛附近的翻转。

## 独立服务与原生集成

独立服务便于隔离运行时和定位故障。协议宜采用有长度上限的消息、请求 ID、帧 ID、超时和明确错误结果；图像读写应采用临时文件完成后原子替换等交接方式。文件修改时间只能辅助发现旧图，不能代替触发和帧的身份关联。

进程内原生推理减少通信环节，但要处理宿主进程架构、ABI、内存所有权、线程安全、运行库版本和 DLL 生命周期。必须对照实际安装版本的 SDK 验证，教学代码不代表任何具体宿主的兼容认证。

## 后处理策略的取舍

本例选择所有候选中分数最高的一行，分数等于门槛时通过方向判定，同分保留原始顺序。其他策略也可能合理，但应明确处理多候选、同分、无候选和未知类别。示例会拒绝非有限值、非法分数和无效框，这是公开示例的输入契约，不声称复刻实际交付版本。

分类置信度不是校准后的缺陷概率。门槛应在独立验证集上结合误放、误剔代价选择；不要只用历史错误集合调参，再把回放结果作为总体准确率。无候选只能表示模型未检出，不能断言物理空料。

## 可复现验证

- 单元测试：方向、门槛边界、同分、空输出、坏输出与错帧。
- 预处理对比：同一份公开输入字节、同一 ROI 与模型契约、逐层定位差异。
- 集成测试：超时、断连接、坏图、未完成写入、并发请求与恢复后的当前帧。
- 真实系统验证：独立标注、连续运行、分开统计误剔/误放/采集异常及端到端耗时。

最后两项需要用户自己的授权环境。本仓库执行单元测试与六张真实样例回放，不包含实际产线验收结果。

## 发布与回退

将代码、权重、依赖清单和配置一起版本化。本仓库公开实际权重与最小回放样例；完整设备配置由部署环境管理。升级时准备成套回退，避免组件错配。日志采用最小必要字段，不把人员或企业名称写入公共问题单。
